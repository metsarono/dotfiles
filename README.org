DotCortex is Mètsàtron's literate operating layer: a grimoire of Org-mode
source that tangles into host-scoped overlays, then the QuickSilver Loom,
powered by Maak and GNU Stow, weaves those overlays into living machines.

#+BEGIN_QUOTE
Org sources → tangle → overlay dirs → stow → living machines
#+END_QUOTE

This is not a generic starter kit. It is a personal, public, reproducible
system for keeping code, memory, package manifests, desktop style, and machine
rituals in one canonical shape.

| Layer      | Tooling / shape                                      |
|------------+-------------------------------------------------------|
| Source     | Org-mode files at repo root                           |

* What lies here?

- A literate dotfiles system built from Org-mode source blocks
- Overlay directories for shared, Linux, distro, and machine-specific state
- A Guile-powered =loom= control plane, built on Maak, for stow, packages, bootstrap, and health

- LainCore styling for terminals, GTK, editor themes, fonts, FastFetch, and desktop polish
- Multi-machine support for ThinkPads, Termux, and future hosts without making private state public

* Quick Start

** Fresh machine bootstrap

#+BEGIN_SRC sh
# 1. Clone
git clone --recursive https://gitlab.com/metsatron/dotfiles.git ~/DotCortex

# 2. Run the bootstrap (installs deps, tangles, stows, applies manifests)
cd ~/DotCortex && bash INSTALL.sh

# 3. Log out and back in, then:
loom              # see all available verbs
loom pip:health   # verify Python
loom npm:health   # verify Node
#+END_SRC

The bootstrap installs: git, stow, emacs-nox, python3, nodejs, npm, keychain,
zoxide, jq, GNU Guix, and applies the declared package manifests. After
bootstrap, use =loom= verbs or =make= targets for ongoing management.

** Existing machine flow

#+BEGIN_SRC sh
cd ~/DotCortex
make tangle
loom stow:x230      # X230
loom stow:t480s     # T480s
loom stow:s24       # Termux / S24
loom pip:apply
loom npm:apply
loom guix:apply
#+END_SRC

For NetworkManager/Tailscale DNS ownership, [[file:services-network-dns.org][services-network-dns.org]]
provides a narrow =tailscale-dns-setup= plan/apply/check flow. It protects
Tailscale-managed resolver files from DHCP-triggered overwrites without
restarting networking, and preserves existing resolved/resolvconf integration.
The same module supports inspected ifupdown/dhclient hosts via =--dhclient=.

When Guix or Loom is not available yet, bootstrap with Make:

#+BEGIN_SRC sh
STOW_PKGS='all linux debian t480' make safe-stow
#+END_SRC

** Module namespaces
Root sources are namespaced by family, and every module stays under a 100 KB budget (≈25k tokens) so any single file fits a small-model context window. =org-style-lint= warns on breach at every =make tangle=; when it fires, split along section seams and keep headline text stable so tangle fences only change their file path. It also warns when a root module's name is not lowercase-kebab or matches no prefix in this table (the prefixes are read from this table; pre-existing standalone modules are allowlisted in the lint): a new family is added here in the same commit, never invented in a filename.

| Prefix         | Family                                                                                       |
|----------------+----------------------------------------------------------------------------------------------|
| =package-*=    | package-manager manifests and tooling; Guix habitat profiles in =package-guix-habitat.org=    |
| =desktop-*=    | desktop environments (Plasma, XFCE)                                                          |
| =emacs-*=      | Emacs profiles (Doom, Spacemacs)                                                             |
| =agents-*=     | agent doctrine, skills (=agents-skills*.org= by scope), hooks, bots, MCP, Hermes, wiki       |
| =services-*=   | host services; the agent-sessiond / agent-top suite in its own modules                       |
| =sanctuary-*=  | Virtual Habitat distrobox guests — engine in =sanctuary-distrobox.org=, one file per guest   |
| =tools-*=      | tool suites split out of =tools.org= (=tools-ai-usage.org=)                                  |
| (standalone)   | environment modules: =shell=, =term=, =mux=, =x11=, =style=, =fonts=, =icons=, =menu=, …     |

** Overlays (unchanged, honored)
- =all/= shared everywhere

** Literate sources
Org files live alongside  =orgsrc/= and =<module>.org=. They *tangle* into existing paths
(e.g. =all/.bashrc=, =arch/.xinitrc=). This allows incremental adoption: keep your current files working while you migrate content.

** Stow ritual (priority order)
#+BEGIN_SRC sh
loom stow:x230
loom stow:t480s
loom stow:s24

# bootstrap/fallback when loom is unavailable:
STOW_PKGS='all linux debian x230' make safe-stow
#+END_SRC

** Batch update: TOC → Tangle → Optional profile apply
Emacs in batch updates dynamic TOC blocks and tangles files. Targets below assume GNU Emacs is installed.

** Guix, profiles, and when targets run
- =make all= runs only =toc → tangle → guix-dirs=. It does not build profiles.
- Run =make guix-core= whenever you change =all/.config/guix/manifests/core.scm=.
- If you really want profiles built on every =make all=, add =guix-core= to the dependencies of =all=. This repo uses explicit targets to avoid surprise rebuilds.

** Session wiring
Linux only.

- =linux/.xsessionrc.d/20-guix-core-profile.sh= loads the named core profile so GUI apps launched from menus see Guix paths.
- =linux/.config/environment.d/20-gtk-appmenu.conf= exports GTK AppMenu variable session wide on Linux, safe across DEs.
- Make them live with:
#+BEGIN_SRC sh
cd ~/DotCortex && loom stow:x230
logout
#+END_SRC

** Remove or change specs in =core.scm=
- Re-run:
#+BEGIN_SRC sh
make guix-core
guix gc
#+END_SRC
- The profile reconciles with the manifest. Removed specs are unlinked from that profile. Store bytes free on =guix gc=.

** Quick test commands
- Preview stow impact:
#+BEGIN_SRC sh
make preview-stow
#+END_SRC

- Check global menu stack is alive:
#+BEGIN_SRC sh
pgrep -af appmenu-registrar || echo "registrar missing"
echo "$GTK_MODULES"
#+END_SRC

** Requirements
- GNU Make ≥ 3.82 (for =.RECIPEPREFIX=)
- Emacs (batch mode — =emacs-nox= is sufficient)
- GNU Stow
- Python 3 + pip (for pip manifest)
- Node.js + npm (for npm manifest)
- Flatpak (for the bridge targets)
- GNU Guix (for =guix-*= targets and =loom= control plane)
- All of these are installed by =INSTALL.sh=

** Global variables
These can be overridden per run (e.g. =EMACS=, =GUIX=):
- =EMACS=: default =emacs=
- =SCRIPT=: =all/.local/bin/dotfiles-batch.el=
- =ROOT=: repo root (=${PWD}=)
- =GUIX=: default =guix=
- =GUIX_HOME=: =~/.config/guix=
- =EXTRA=: =~/.guix-extra-profiles=

** Target overview (at a glance)
| Target                 | What it does                                                   |
|------------------------+----------------------------------------------------------------|
| =toc=                  | Refresh Org dynamic blocks (TOC/indexes) via batch Emacs.     |
| =tangle=               | Tangle Org code blocks into overlay paths (e.g., all/, linux/).|
| =guix-dirs=            | Ensure Guix ancillary dirs exist (via guix-mkdirs if present). |
| =all=                  | Meta-target: toc → tangle → guix-dirs.                         |
| =guix-pull=            | Run guix pull to fetch latest Guix packages.                  |
| =guix-core=            | Build core Guix profile from core.scm manifest.               |
| =guix-dev=             | Build dev profile (after guix-core).                          |
| =guix-gc=              | Run guix gc to garbage-collect unused paths.                  |
| =safe-stow=            | Preview stow, back up real files, then apply stow safely.     |
| =preview-stow=         | Dry-run preview of stow changes (no actual writes).           |
| =bridge-flatpak=       | Apply font/cursor bridge overrides for Flatpak.               |
| =bridge-flatpak-reset= | Remove overrides added by bridge-flatpak.                     |
| =x11-apply=            | Ensure merged ~/.xsessionrc includes cursor/env fixes.         |

flatpak override --user --show | grep -E 'FONTCONFIG_FILE|XCURSOR_PATH' || true
#+END_SRC

** What each powered feature actually does
*** Safe Stow (=safe-stow=)
- Runs =stow -n= on packages (=all linux debian x230=) to **detect** files that aren’t symlinks yet.
- For each real file it would overwrite, copies a timestamped backup:
  =~/path/file.bak-YYYYmmdd-HHMMSS=
- Then runs =stow PKG= for each package in order.

Verify:
#+BEGIN_SRC sh
readlink -f ~/.xsessionrc
ls -l ~/.local/bin/flatpak-desktop-bridge
#+END_SRC

Rollback (per file):
#+BEGIN_SRC sh
mv ~/.xsessionrc.bak-YYYYmmdd-HHMMSS ~/.xsessionrc
#+END_SRC

*** X11 apply (=x11-apply=)
- Re-tangles (idempotent), stows =x230=, and ensures your merged =~/.xsessionrc= contains:
  - your original GTK_CSD/LD_PRELOAD logic, and
  - a **non-clobbering** cursor search path:
    =XCURSOR_PATH=$HOME/.icons:/usr/local/share/icons:/usr/share/icons=

Verify:
#+BEGIN_SRC sh
sed -n '1,80p' ~/.xsessionrc
printenv XCURSOR_PATH || echo "(will be set on next X session start)"
#+END_SRC

*** Flatpak bridge (fonts + cursors) (=bridge-flatpak=)
- Tangle+stow first (keeps scripts/configs current).
- Points all Flatpaks at a versioned fonts config:
  - =FONTCONFIG_FILE=${HOME}/DotCortex/linux/.flatpak/fontconfig/fonts.conf=
  - That config includes:
    - your user fonts: =/home/metsatron/.local/share/fonts= (and legacy =~/.fonts= if used)
    - host fonts via the Flatpak bridge: =/run/host/usr/share/fonts= and =/run/host/usr/local/share/fonts=
- Exposes cursors to Flatpaks dynamically (no theme is forced):
  - =XCURSOR_PATH=$HOME/.icons:/run/host/usr/local/share/icons:/run/host/usr/share/icons=
- Unsets =LD_PRELOAD= inside Flatpaks to avoid host leakage.

Verify:
#+BEGIN_SRC sh
flatpak override --user --show | grep -E 'FONTCONFIG_FILE|XCURSOR_PATH' || true
sed -n '1,40p' ~/DotCortex/linux/.flatpak/fontconfig/fonts.conf

# Inside apps:
flatpak run --command=sh md.obsidian.Obsidian -c \
  'fc-cache -f >/dev/null 2>&1; fc-match "SFMono Nerd Font"; fc-match "SFMono Nerd Font Mono"'
flatpak run --command=sh one.ablaze.floorp -c 'fc-match "SFMono Nerd Font"'
flatpak run --command=sh one.ablaze.floorp -c 'echo $XCURSOR_PATH'
#+END_SRC

Expected:
- You see =SFMonoNerdFont-*.otf= matches in both apps.
- =XCURSOR_PATH= shows your user icons plus host icon dirs.

*** Flatpak bridge reset (=bridge-flatpak-reset=)
- Removes only the overrides the bridge set:
  - Unsets =FONTCONFIG_FILE= and =XCURSOR_PATH= at =--user= scope.
  - Removes any per-app env bindings added by the bridge.
- Does **not** touch your fonts or icons on disk.

Verify:
#+BEGIN_SRC sh
flatpak override --user --show | grep -E 'FONTCONFIG_FILE|XCURSOR_PATH' || true
#+END_SRC

** Submodule Policy
Submodules are treated as tracked vendor checkouts with local working trees.

- Refreshing a submodule on disk is operational-only unless a canonical DotCortex source file owns the path and update intent.
- A pointer bump may be committed only when the corresponding submodule is declared in DotCortex source and the update is deliberate.
- Parent `.gitignore` must not be used to hide files inside a submodule.

If your own configs are untracked inside a submodule:

- If they belong in DotCortex, promote them into the DotCortex-owned source that generates or configures that path.
- If they are local-only state, keep them local to the submodule via the submodule's own exclude file or `.gitignore`.
- If the submodule is third-party and you need to persist custom config, put the config beside the submodule in DotCortex and point the submodule tooling at it. Do not depend on an untracked vendor worktree for durable config.

** Troubleshooting
- Emacs “no version information available (libxml2)”
  This is benign on mixed Guix/Ubuntu setups; batch Emacs still runs. To silence it, align libxml2 versions or use a non-Guix Emacs for tangling.

- Fonts inside Flatpaks still resolve to DejaVu
#+BEGIN_SRC sh
make bridge-flatpak
flatpak run --command=sh md.obsidian.Obsidian -c \
  'fc-cache -f >/dev/null 2>&1; FC_DEBUG=4 fc-match "SFMono Nerd Font"'
#+END_SRC
Check that =/home/metsatron/.local/share/fonts= is listed and =FONTCONFIG_FILE= points into =DotCortex/linux/.flatpak/...=.

- Cursor theme not picked by some apps
Flatpaks see =XCURSOR_PATH=; the actual theme is chosen by the host. Ensure the selected theme exists in =~/.icons= or =/usr/share/icons=. We intentionally **don’t** set =XCURSOR_THEME= globally to keep it dynamic.

* Templates Directory

The `~/Templates/` directory provides structured starter files for use in Thunar's
"Create Document" context menu (or any other file manager that supports XDG Templates).

** Purpose
- Quick creation of new files with prefilled structure
- Cross-OS compatibility (even on systems without Thunar)
- Shared, stowable dotfiles-based templates

** Structure
We maintain a one-level-deep layout to avoid clutter in file manager menus:

#+BEGIN_EXAMPLE
Templates/
  Bash Script.sh
  Zsh Script.zsh
  Plain Text.txt
  README.md
  Obsidian Note.md
  Logseq Note.md
  Code/
  Emacs/
  Notes/
  Media/
  OpenDocument/
  Projects/
#+END_EXAMPLE

** Philosophy
- Keep most universal, OS-level, cross-project files in the *root*.
  - e.g. README.md, Plain Text.txt, Bash Script.sh
- Use subfolders for niche or domain-specific templates.
  - e.g. Code/, Emacs/, Notes/, Media/
- This preserves a clean, practical right-click menu.

** Usage
- Simply add or edit templates in ~/Templates/
- They will appear automatically in Thunar's "Create Document"
- Fully stow-compatible across systems

** Example Command to View Structure
Run from within Templates:

#+BEGIN_SRC bash
tree -a -L 2
#+END_SRC

This will show the top-level and immediate subfolder contents for easy verification.

** Notes
- Executable bits are not preserved when using "Create Document".
  - Scripts will need `chmod +x` after creation.
  - Templates contain correct shebangs for easy editing.
- Designed to be OS-agnostic.
  - Works on Linux (Thunar, Dolphin)
  - Safe to store on macOS, Windows, WSL
  - Can be used with CLI tooling
