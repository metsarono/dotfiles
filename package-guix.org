* Intent
A minimal, sovereign Guix install on a Debian-family host, managed from this repo.
We keep privileged steps explicit, package state declarative, and paths inside overlays.
Nothing in here overwrites your shell files directly, it only adds small blocks that tangle into your existing exports files.

* Layout
- Guix channels, profiles, manifests under =all/.config/guix/=
- Helper scripts under =all/.local/bin/=
- Shell exports for PATH added in tiny, self-contained blocks that tangle into =all/.bash_exports= and =all/.zsh_exports=
- No files removed, only appended sections with clear sentinels

** Inference profile — CPU-tuned llama.cpp and whisper.cpp

Local CPU inference, kept out of =core.scm= on purpose and applied only to machines that
should actually run models.

*Why this profile exists.* Guix's stock =ggml= and =ggml-for-whisper= are built for baseline
x86_64. Disassembling =libggml-cpu.so= from both shows *zero* =%ymm= (AVX/AVX2), *zero* =%zmm=
(AVX-512) and *zero* =vfmadd= (FMA) against roughly 13k =%xmm= — pure SSE, on CPUs whose
=/proc/cpuinfo= advertises =avx avx2 fma=. ggml's quantized dot-product kernels have
hand-written AVX2 paths and fall back to generic scalar C without them. Measured on the
T480s: ~13 tok/s embedding locally, against ~890 tok/s from a machine whose llama.cpp was
compiled normally (17490 AVX2, 8972 AVX-512, 1861 FMA instructions).

*Why not =--tune=.* =guix build --tune=native= prints "tuning llama-cpp for CPU skylake" and
"tuning ggml for CPU skylake" and then emits a *byte-identical store path*. It is a verified
no-op for these packages and the reassuring message is a trap. =--with-configure-flag= on the
ggml packages is the lever that actually produces new derivations.

*Why =GGML_CPU_ALL_VARIANTS= and not =GGML_NATIVE=.* The first attempt used
=-DGGML_NATIVE=ON= and failed at configure time, with upstream ggml itself naming the answer:
"GGML_NATIVE is not compatible with GGML_BACKEND_DL, consider using GGML_CPU_ALL_VARIANTS"
(=src/ggml-cpu/CMakeLists.txt:374=). Guix builds these packages with =GGML_BACKEND_DL=ON= and a
=GGML_BACKEND_DIR= pointing at =lib/backends=, so the dynamic-backend path is not optional here.

That constraint turns out to be a gift. =GGML_CPU_ALL_VARIANTS=ON= compiles a full set of CPU
backends — sandybridge, haswell, skylake-x, icelake, alderlake and friends — and ggml picks the
best one your CPU supports at load time. So the build is *portable*: one derivation is correct
on the T480s and T480 (AVX2), on the T1700's Haswell Xeon when it lands, and on anything added
later, with no =-march=native= lock-in and no per-machine divergence. It costs a longer compile
(several variants instead of one) and a larger profile, paid once.

*Verify, never assume.* A silent regression here looks exactly like success — the profile builds,
the binaries run, and they are simply slow. After building, count the vector instructions:
=objdump -d ~/.guix-extra-profiles/inference/inference/lib/backends/libggml-cpu-haswell.so | grep -c '%ymm'=
A zero means the variant build did not take.

*Who gets it.* Machines that do local CPU inference as a fallback when the primary inference
node is unreachable: currently the T480s and T480, and the Precision T1700 when it lands
(Xeon E3-1246 v3, Haswell — AVX2 + FMA). Deliberately *not* the X230: it is the fleet
fileserver, thermally degraded, and does no local inference (ruling 2026-07-25).

#+BEGIN_SRC scheme :tangle all/.config/guix/manifests/inference.scm :mkdirp yes
;; ~/.config/guix/manifests/inference.scm
;; CPU-tuned local inference. Apply with `loom guix:inference-apply'.
;; Deliberately excluded from core.scm — see the notes in package-guix.org.
(use-modules (gnu packages)
             (guix transformations)
             (local packages llama-swap))

;; ggml and ggml-for-whisper are separate packages carrying the same defect; both need the flag.
;;
;; NOT GGML_NATIVE. Guix builds these with GGML_BACKEND_DL=ON, and ggml's own CMake rejects
;; the combination outright: "GGML_NATIVE is not compatible with GGML_BACKEND_DL, consider
;; using GGML_CPU_ALL_VARIANTS" (src/ggml-cpu/CMakeLists.txt:374). ALL_VARIANTS compiles one
;; backend per microarchitecture and dispatches at load time, which is both what upstream
;; wants here and portable across the whole fleet — no -march=native lock-in.
;;
;; Verify after building, do not assume — a failed variant build still produces a working,
;; merely slow, profile:
;;   objdump -d <profile>/lib/backends/libggml-cpu-haswell.so | grep -c '%ymm'
(define tune-ggml
  (options->transformation
   '((with-configure-flag . "ggml=-DGGML_CPU_ALL_VARIANTS=ON")
     (with-configure-flag . "ggml-for-whisper=-DGGML_CPU_ALL_VARIANTS=ON"))))

(packages->manifest
 (cons llama-swap
       (map (compose tune-ggml specification->package)
            (list "llama-cpp"      ; Recall embeddings (Qwen3-Embedding) + local chat fallback
                  "whisper-cpp")))) ; whisper-transcribe, whisper-hotkey dictation, telegram voice
#+END_SRC

* Agent profiles — per-agent Guix lane (rule 22 Category B)

Per-agent Guix profiles for =agent-<tool>= users (see =agents-users.org= §Agent User
Bootstrap). The shared store is the multi-user mechanism: agents get their own
profiles built from manifests here, using the *human's channel-pinned guix from
the store* (never the =/usr/local/bin/guix= fossil — its testimony is unreliable,
see dotcortex-gotchas). Agents never borrow binaries from the human home; store
paths are world-executable by design.

Apply is dry-run by default; =--apply= mutates. Per the loom ruling
(Mètsàtron 2026-06-11): all guix installs go through this lane, never raw
=guix install=.

#+BEGIN_SRC bash :tangle all/.local/bin/agent-guix-apply :shebang "#!/usr/bin/env bash"
# ~/DotCortex/all/.local/bin/agent-guix-apply
# Builds per-agent Guix profiles from all/.config/guix/manifests/agents/*.scm.
# DRY-RUN unless --apply. Run as the human operator (uses sudo per agent).
# The manifest is copied into the agent home first so no DotCortex read
# permission is assumed; the guix binary is the human's channel-pinned one

** Foreign OpenRC hosts (Honey)

The block above assumes systemd. On an OpenRC host (Devuan with OpenRC as its service manager) the upstream installer detects "sysv-init" and writes an LSB script that OpenRC never starts at boot, which is how T480's daemon stayed dead from 2026-06-28 to 2026-07-12. =guix-foreign-bootstrap= is the manual's binary installation made deterministic for these hosts: a signed release tarball verified in a throwaway keyring against the upstream release signers, the classic root daemon with =guixbuild= users, the native OpenRC service below, =/usr/local/bin/guix= for every user, and the fleet's substitute keys (ci and bordeaux from the release, nonguix from this checkout). It never prompts and edits no shell files. It refuses when Guix is already present, and =--dry-run= downloads and verifies without changing anything.

After the bootstrap the operator account pulls the fleet channel pin (=guix pull -C all/.config/guix/channels.scm=), and =agent-guix-apply= builds each agent's node profile from that pinned guix, exactly as on kikin. Honey was bootstrapped this way on 2026-09-26, with Mètsàtron's go, for the tanuki bots' =agent-claude= node profile.

#
# The upstream manual's binary installation, made deterministic: a verified
# release tarball, the classic root daemon with guixbuild users, DotCortex's
# OpenRC guix-daemon service (not the installer's LSB script, which OpenRC
# never starts at boot; T480, 2026-07), the fleet's substitute keys. No prompts,
# no shell-prompt or bashrc edits, nothing outside what Guix itself needs.

    3CE464558A84FDC69DB40CFB090B11993D9AEBB5   # Ludovic Courtès
    27D586A4F8900854329FF09F1260E46482E63562   # Maxim Cournoyer
    A28BF40C3E551372662D14F741AAE7DCCA3D8351   # Efraim Flashner

Usage: guix-foreign-bootstrap [--dry-run] <dotcortex-checkout>

** Channel pin (fleet-wide revision lock)
The block was titled "seed only once" and carried no =(commit ...)= for its whole
life, so every =guix pull= on every machine took whatever master happened to be.
The fleet duly drifted onto three different revisions (X230 =b66d313= Jul 10,
T480s =1fef20a= Jul 13, T480 =9e5a77e= Jun 08), and that drift is not cosmetic:

*It breaks substitute sharing.* Guix store items are content-addressed over the
whole derivation graph, so a different guix revision means different store
hashes. Machine A builds a package, machine B asks for it, the hashes do not
match, and B rebuilds it from source. A peer substitute mesh across unpinned
machines mostly *misses* — you would build the whole sharing apparatus and still
compile everything twice.

That is the reason, and it is sufficient. It is *not* the reason =guix offload=
fails to the T480 — an earlier revision of this comment claimed it was, and that
claim was wrong. The T480 is now on this exact pinned revision and its
=guix archive= is still broken; see the quarantine note in =/etc/guix/machines.scm=
and the open research question in the ledger. Recording the correction here
because a false root cause left in a comment is worse than no comment: the next
agent stops looking.

Pinned to the T480s revision, which was the newest in the fleet. To move the
fleet forward: bump both commits here (take them from =guix describe -f channels=
on a machine that has pulled), tangle, then =guix pull= on each machine.
Deliberate, together, or not at all.

# Guix's glibc finds locale data only via GUIX_LOCPATH. The profile's own
# etc/profile does NOT export it, and the X session never sets it, so a
# Guix binary launched from a keyboard shortcut or autostart entry sees
# LANG=en_US.UTF-8 with no locale data behind it. Two failure modes follow,
# and both were observed: rofi calls setlocale(), fails, and exits 1 (every
# rofi shortcut silently dead); or, with LANG also unset, it starts in the C
# locale, where fontconfig scores Noto Color Emoji below Symbola and colour
# emoji degrade into outline glyphs and tofu. An interactive zsh escapes both
# because .zshenv sets GUIX_LOCPATH -- which is why `rofi -dmenu` from a
# terminal always worked while the identical shortcut did not.
if [ -d "$GUIX_PROFILE/lib/locale" ]; then
  GUIX_LOCPATH="$GUIX_PROFILE/lib/locale"
  export GUIX_LOCPATH
fi

    *":$dir:"*) ;;
    *) XDG_DATA_DIRS="${XDG_DATA_DIRS:+$XDG_DATA_DIRS:}$dir" ;;
  esac
}

# Guix profile activation can leave XDG_DATA_DIRS containing only the profile
# currently sourced. Desktop menus need every active Guix profile plus the
# system application directories.
for profile in "$HOME/.guix-profile" "$HOME"/.guix-extra-profiles/*/*; do
  [ -d "$profile" ] || continue
  case "$profile" in
    *-link) continue ;;
    # Room and sanctuary profiles belong to their own rooms/containers, which
    # source them explicitly. Adding their share/ to the HOST session's
    # XDG_DATA_DIRS ranks their .desktop files ABOVE /usr/share, so a Guix build
    # silently shadows the Debian app -- its Exec= is an absolute /gnu/store path,
    # so PATH never even comes into it. A Guix GTK app resolves modules and themes
    # from the Guix store, so it cannot load Debian's appmenu-gtk-module and loses
    # the global menu, and falls back to Adwaita/CSD instead of the host GTK theme.

# The Guix profile sets GIO_EXTRA_MODULES to its own gio/modules dir, which
# contains GIO modules built against Guix GLib (currently 2.83+). System
# binaries (flatpak-session-helper, xdg-desktop-portal) link against the
# system GLib (2.72 on Ubuntu 22.04) and lack newer symbols like
# g_once_init_enter_pointer — causing them to crash on startup.
#
# /etc/X11/Xsession.d/95dbus_update-activation-env runs after this script and
# calls `dbus-update-activation-environment --systemd --all`, which bakes the
# entire current environment — including GIO_EXTRA_MODULES — into the systemd
# user session. Removing it from the systemd session here, before step 95
# runs, prevents it from ever reaching system service processes.
#
# Guix-built apps find their own GIO modules via their compiled-in rpath
# (/gnu/store/.../lib/gio/modules), so this does not break Guix apps.
if systemctl --user is-active --quiet default.target 2>/dev/null; then
  systemctl --user unset-environment GIO_EXTRA_MODULES 2>/dev/null || true
fi
unset GIO_EXTRA_MODULES

# The Guix profile sets GST_PLUGIN_SYSTEM_PATH to ONLY its own plugin dir. That
# var REPLACES (does not append to) GStreamer's compiled-in OS default, so every
# system app in this session (e.g. Debian Quod Libet, GStreamer 1.26) stops
# scanning /usr/lib/.../gstreamer-1.0 and loses pulsesink -> playback dies with
# "No GStreamer audio sink found". This runs once for the whole session, so it
# fixes every GUI app regardless of which shell launches it. Append the OS
# plugin dirs back: each GStreamer core silently skips version-mismatched
# plugins, so Guix (1.28) and system (1.26) apps each keep their own set.
if [ -n "${GST_PLUGIN_SYSTEM_PATH:-}" ]; then
  for __gst in "/usr/lib/$(uname -m)-linux-gnu/gstreamer-1.0" /usr/lib/gstreamer-1.0 /usr/lib64/gstreamer-1.0; do
    [ -d "$__gst" ] || continue
    case ":$GST_PLUGIN_SYSTEM_PATH:" in
      *":$__gst:"*) ;;
      *) GST_PLUGIN_SYSTEM_PATH="$GST_PLUGIN_SYSTEM_PATH:$__gst" ;;
    esac
  done
  export GST_PLUGIN_SYSTEM_PATH
  unset __gst
fi

** Bench fastest Guix channel mirror
#+BEGIN_SRC bash :tangle all/.local/bin/guix-bench-pull :shebang "#!/usr/bin/env bash" :tangle-mode (identity #o755) :mkdirp yes
#!/usr/bin/env bash
# all/.local/bin/guix-bench-pull
set -Eeuo pipefail

BENCH_DIR="${XDG_CONFIG_HOME:-$HOME/.config}/guix/.bench"
CACHE="${BENCH_DIR}/pull-url"
BL="${BENCH_DIR}/pull-blacklist"
SSV="${XDG_CONFIG_HOME:-$HOME/.config}/guix/pull-candidates.ssv"

mkdir -p "$BENCH_DIR"; touch "$BL"

urls_from_ssv() {
  [[ -r "$SSV" ]] || return 1
  awk '
    BEGIN{IGNORECASE=1}
    /^[[:space:]]*#/ {next}           # comments
    NF==0 {next}                      # blank lines
    NR==1 && $1 ~ /^url$/ {next}      # optional header row
    {print $1}                        # first column is the URL
  ' "$SSV"
}

declare -a CANDS=()
if [[ -n "${GUIX_PULL_CANDIDATES:-}" ]]; then
  # space-separated URLs override SSV
  read -r -a CANDS <<< "$GUIX_PULL_CANDIDATES"
else
  mapfile -t CANDS < <(urls_from_ssv || true)
  # final fallback if SSV missing/empty
  if [[ ${#CANDS[@]} -eq 0 ]]; then
    CANDS=( "https://codeberg.org/guix/guix.git"
            "https://git.cbaines.net/guix/guix"
            "https://git.savannah.gnu.org/git/guix.git"
            "https://mirror.git.savannah.gnu.org/r/guix.git" )
  fi
fi

have_git=0; command -v git >/dev/null 2>&1 && have_git=1

probe_git() { # url -> seconds
  local u="$1"
  local t
  t="$( TIMEFORMAT=%R; { time git ls-remote --heads --tags --refs --timeout=12 "$u" >/dev/null 2>&1; } 2>&1 )" || return 1
  printf '%s\n' "$t"
}
probe_tcp() { # host:443 reachable?
  timeout 4 bash -lc "exec 3<>/dev/tcp/$1/443" 2>/dev/null
}

rows=()
for u in "${CANDS[@]}"; do
  grep -qxF "$u" "$BL" && continue
  host="$(sed -n 's#https\?://\([^/]*\).*#\1#p' <<<"$u")"
  probe_tcp "$host" || continue
  t=""
  if [[ $have_git -eq 1 ]]; then
    t="$(probe_git "$u" || true)"
  fi
  [[ -z "$t" ]] && continue
  rows+=("$t $u")
done

# choose the fastest
best="$(printf '%s\n' "${rows[@]}" | sort -n | awk 'NR==1{print $2}')"

if [[ -z "${best:-}" ]]; then
  echo "no-viable-mirror" >&2
  exit 2
fi

printf '%s\n' "$best"
#+END_SRC

#!/usr/bin/env bash
# Guix Env Bypassing Host Wrapper

set -euo pipefail

# Preserve a sane locale
LANG="${LANG:-C.UTF-8}"
LC_ALL="${LC_ALL:-}"

# Always disable CSD unless explicitly overridden
GTK_CSD="${GTK_CSD:-0}"

# If nocsd is available and LD_PRELOAD is not already set, use it
if [ -z "${LD_PRELOAD-}" ] && [ -e /usr/lib/x86_64-linux-gnu/libgtk3-nocsd.so.0 ]; then
  LD_PRELOAD="/usr/lib/x86_64-linux-gnu/libgtk3-nocsd.so.0"
fi

# Strip Guix profile bins out of PATH for this wrapper only
strip_guix_from_path() {
  local elem out=""
  IFS=':' read -r -a parts <<< "${PATH:-}"
  for elem in "${parts[@]}"; do
    [ -z "$elem" ] && continue
    if [[ "$elem" == "$HOME/.config/guix/current/bin" ]] \
       || [[ "$elem" == "$HOME/.guix-profile/bin" ]] \
       || [[ "$elem" == "$HOME/.guix-extra-profiles/"*"/bin" ]]; then
      continue
    fi
    if [ -z "$out" ]; then
      out="$elem"
    else
      out="$out:$elem"
    fi
  done
  printf '%s\n' "$out"
}

CLEAN_PATH="$(strip_guix_from_path)"

# but keep the bits that matter for X, DBus, global menu, nocsd, Qt and Flatpak metadata.
exec env -i \
  HOME="$HOME" \
  PATH="$CLEAN_PATH" \
  LANG="$LANG" \
  LC_ALL="$LC_ALL" \
  DISPLAY="${DISPLAY:-}" \
  XAUTHORITY="${XAUTHORITY:-}" \
  DBUS_SESSION_BUS_ADDRESS="${DBUS_SESSION_BUS_ADDRESS:-}" \
  XDG_RUNTIME_DIR="${XDG_RUNTIME_DIR:-}" \
  XDG_CURRENT_DESKTOP="${XDG_CURRENT_DESKTOP:-}" \
  XDG_SESSION_TYPE="${XDG_SESSION_TYPE:-}" \
  XDG_CONFIG_HOME="${XDG_CONFIG_HOME:-$HOME/.config}" \
  XDG_DATA_DIRS="${XDG_DATA_DIRS:-}" \
  XDG_DATA_HOME="${XDG_DATA_HOME:-$HOME/.local/share}" \
  GTK_MODULES="${GTK_MODULES:-}" \
  GTK_CSD="$GTK_CSD" \
  LD_PRELOAD="${LD_PRELOAD:-}" \
  QT_QPA_PLATFORMTHEME="${QT_QPA_PLATFORMTHEME:-}" \

** System Python override — Guix python3 must not shadow the distro
On Debian-family machines the Guix core profile ships =python3=, and the profile
bin dir sits in PATH ahead of =/usr/bin=. Every =#!/usr/bin/env python3= shebang
in distro tooling (e.g. Vendefoul Wolf's =gksu= at =/usr/local/bin/gksu=) then
resolves to Guix Python — which lacks =_tkinter= and whose =GUIX_PYTHONPATH=
site-packages routinely drift out of sync with the interpreter version. Result:
distro GUI tools crash with =ModuleNotFoundError=.

=~/.local/bin= is ordered ahead of the Guix profile bin in PATH (see
=shell.org=), so this wrapper makes =python3= resolve to the distro interpreter
for shells, =env=-shebangs, and GUI-launched subprocesses alike. Guix-built
applications are unaffected — they reference their interpreter by absolute
=/gnu/store/...= path, never through PATH. Guix Python stays reachable
explicitly at =~/.guix-extra-profiles/core/core/bin/python3=.

Scoped to =debian/= because it assumes =/usr/bin/python3= exists.

#+BEGIN_SRC sh :tangle debian/.local/bin/python3 :shebang "#!/bin/sh" :mkdirp yes
exec /usr/bin/python3 "$@"
#+END_SRC

** Rofi core wrapper (single entry point)
#+BEGIN_SRC bash :tangle linux/.local/bin/rofi-core :shebang "#!/usr/bin/env bash" :mkdirp yes
PROFILE="$HOME/.guix-extra-profiles/core/core"

# Load core Guix profile (PATH, XDG_DATA_DIRS, etc.) if present.
# This MUST happen before `set -u`: the profile's own script dereferences
# GIO_EXTRA_MODULES bare, and under nounset that aborts the wrapper before it
# ever reaches rofi, taking every caller down with it (this is what silently
# killed the Super+x action menu).
if [ -r "$PROFILE/etc/profile" ]; then
  # shellcheck source=/dev/null
  . "$PROFILE/etc/profile"
fi

# The Guix profile's own etc/profile does not export this, so XFCE keybindings
# (which exec this wrapper directly, skipping zsh's login-shell init) never see
# it. Without it, Guix's glibc can't find its own locale data, setlocale()
# fails, and rofi 2.0.0 hard-exits instead of just warning like older rofi did.
[ -d "$PROFILE/lib/locale" ] && export GUIX_LOCPATH="$PROFILE/lib/locale"

set -euo pipefail

# Defer everything else to rofi, untouched
exec "$PROFILE/bin/rofi" "$@"
#+END_SRC

* Notes
- Guix Home is intentionally not enabled here, since you use literate dotfiles as the source of truth. We keep Guix focused on packages and profiles.
- If you ever add =nonguix=, you must explicitly authorize its substitute key. Keep that ritual documented alongside the channels pin.
- Guix can install many tools that overlap with apt, snaps, or flatpaks. Prefer one source per tool to reduce path ambiguity.

* Known issue: substitute key authorization missing after install (hours of source builds)
:PROPERTIES:
:CREATED:  [2026-06-28]
:END:

After a fresh Guix install (or after =guix pull= on a machine where bordeaux/nonguix keys were never authorized), =guix:apply= silently rejects substitutes from bordeaux and builds everything from source.  This can add hours — Emacs alone is 45–90 min from source.

Root cause: INSTALL.sh only authorized =ci.guix.gnu.org=.  Both =bordeaux.guix.gnu.org= and =substitutes.nonguix.org= need explicit key authorization.  Additionally, the sysv-init =guix-daemon= init script shipped with no =--substitute-urls= arg, so the daemon never queries =substitutes.nonguix.org= at all (nonguix packages — ZFS, winetricks, etc. — always built from source regardless of key status).

Fix: run the authorize block in the *Substitutes: authorize keys* section above, or re-run =INSTALL.sh= on a fresh machine (now fixed to authorize all three servers and set the full =--substitute-urls= arg in the init script).

Detection: =cat /etc/guix/acl | grep -c 'public-key'= — should print =3= (ci + bordeaux + nonguix).  =grep substitute-urls /etc/init.d/guix-daemon= — should show all three URLs.
