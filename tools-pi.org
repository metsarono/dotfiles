* Pi Agent Mistral Studio lane (mistral-pi)

A coordinator-dispatchable worker lane: Pi Agent (=pi=, installed under
=~/.npm-global=, Node 24 from the Guix core profile) talking to the Mistral
Studio API, sitting beside =codex exec= and =vibe -p= as a headless worker
that Fable launches with a brief, a worktree and a report path (build brief:
=helm handoff 2026-10-17-mistral-pi-lane=, Admiral Telegram 7824/7826).

The launcher is =HelmCortex/FORGE/bin/mistral-pi=; this module owns only the
provider and default-model config, which the launcher installs into its own
Pi state directory (=${XDG_STATE_HOME:-~/.local/state}/mistral-pi=, held in
=PI_CODING_AGENT_DIR=) before exec'ing =pi=. The lane therefore never touches
the interactive =~/.pi/agent= configuration.

** Where the key lives

The Studio key is read from the =MISTRAL_API_KEY= environment variable,
referenced by name only — the =apiKey= field below is a =$MISTRAL_API_KEY=
template reference, never a value. The machine-local file
=~/.config/mistral-pi/env= (0600, provisioned by the Admiral from KeePass)
is the only sanctioned source of that variable for this lane. DotCortex is
public: no key, no ids beyond model ids, ever.

** Why the template is not at =all/.pi/agent=

The historical pi config emission (=pi.org= → =all/.pi/agent/=) was removed
by the Hermes decoupling (2026-04), and =~/.pi= is now a HelmCortex NEXUS
stow symlink (=NEXUS/stow/linux/.pi=) holding private mutable Pi state
(auth, sessions). Tangling this template into =all/.pi/agent/= would
stow-conflict with that live directory on every machine. The template
therefore lives at =all/.local/share/mistral-pi/=, a DotCortex-owned
read-only template directory that stows cleanly and contains nothing else.

** Models — verified against the Studio API 2026-10-17

Verified against =GET https://api.mistral.ai/v1/models= (54 ids, key used
only through the environment). The pinned default is =mistral-large-4=
(1 MiB context, vision, function calling). Named alternates:
=mistral-medium-3.5= (256 KiB context) and =devstral-latest=.

Devstral caveat, verified the same day: the Vibe-log id
=devstral-2-123b-instruct-2512= is NOT servable on the Studio API (404 on
=/v1/models=, 400 =invalid_model= on chat completions), and every =devstral-*=
id is absent from this key's model list. =devstral-latest= DOES serve, but the
backend reports the completion's =model= field as =mistral-medium-3-5= —
treat it as a Studio alias, not a distinct weights offering.

** Provider config (template installed by mistral-pi)

The provider speaks pi's native =mistral-conversations= client against
=https://api.mistral.ai= — the same api/baseUrl pi's own built-in
=mistral= provider uses, plus this lane's pinned ids. The handoff asked
for the OpenAI-compatible =/v1= endpoint; that road was walked and
abandoned on evidence (2026-10-17): =openai-completions= sends the
=developer= role, the =store= field and =reasoning_effort: "medium"=,
and Mistral's Studio API rejects all three (422, 422, 400 — bisected by
direct curl and a local request-echo server). The native client needs
no compat flags and surfaces Mistral's real error bodies.

Three traps found live, all recorded for the next traveller:

- The =apiKey= value must carry the dollar sigil: pi 0.85.1's
  =resolve-config-value= treats a bare identifier as a LITERAL key
  (which yields 401), interpolates =$VAR= or =${VAR}= from the
  environment, and runs =!command= values as shell commands. The
  =pi-agent-gotchas= skill still documents the old bare-env-name
  behaviour; it is stale for 0.85.1 (found live 2026-10-17).
- All three pinned models carry =reasoning: false=: with
  =reasoning: true= the native client requests the reasoning prompt
  mode, which is NOT enabled for these models on this key (Mistral
  error 3051, "Reasoning prompt mode is not enabled for this model").
  pi's own built-in catalog marks Mistral's Large line non-reasoning
  too. =--thinking off/high= makes no difference: only =reasoning:
  false= in the model entry avoids the request.
- =pi -p= exits 0 and prints NOTHING when the API errors, so a
  dispatch's success is proven by the run log and on-disk results,
  never by the exit code alone.

* Gemma Google / Antigravity lane

The =pi-antigravity= extension is declared in [[file:package-npm.org][package-npm.org]].
Apply only that package with =ONLY=pi-antigravity loom npm:sync=.
The launcher loads the installed local package, so starting Gemma does not
install dependencies or modify her existing provider configuration.

=gemma-google= uses the same private Pi directory as Gemma's Telegram adapter.
Run it interactively, then =/login antigravity= to sign in with Google.
After sign-in, =/antigravity.refresh= and =/antigravity.models= discover the
account's actual entitlements. Select =antigravity/gemini-4-argon= only when
advertised. The Telegram adapter can use this launcher as =PI_EXECUTABLE=;
its existing explicit provider/model arguments remain authoritative until
an authenticated model is selected in its private environment file.

OAuth credentials, account records, discovery caches, sessions, and the bot
environment remain private mutable state. They are never emitted by DotCortex.
This sign-in TUI starts a separate session and does not resume the Telegram
transcript. Gemma's existing adapter still owns the Telegram session.

#+BEGIN_SRC bash :tangle all/.local/bin/gemma-google :shebang "#!/usr/bin/env bash" :comments no
set -euo pipefail
case "${1:-}" in
    -h|--help)
        printf '%s\n' 'Usage: gemma-google [Pi options]' \
            'Uses Gemma private Pi profile; does not change her Telegram model.' \
            'In interactive Pi: /login antigravity, then /antigravity.refresh and /antigravity.models.' \
            'Complete Google sign-in in your own browser. Paste callback URLs only into the local Pi prompt, never chat.'
        exit 0 ;;
esac
export PI_CODING_AGENT_DIR="${GEMMA_PI_AGENT_DIR:-${PI_CODING_AGENT_DIR:-$HOME/.config/gemma-pi-telegram/pi-agent}}"
prefix="${NPM_CONFIG_PREFIX:-$HOME/.npm-global}"
package="$prefix/lib/node_modules/pi-antigravity"
pi_bin="${PI_ANTIGRAVITY_EXECUTABLE:-$prefix/bin/pi}"
if [[ ! -r "$package/package.json" || ! -x "$pi_bin" ]]; then
    echo 'gemma-google: install the declared Pi packages through DotCortex first.' >&2
    exit 1
fi
if [[ $# -eq 0 ]]; then
    set -- --provider antigravity
fi
exec "$pi_bin" --extension "$package" "$@"
#+END_SRC
